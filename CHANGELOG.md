# Changelog

Semua perubahan penting pada project ini akan didokumentasikan di file ini mengikuti Keep a Changelog dan Semantic Versioning.

## [Unreleased]

### Added

- Worker processes and schedules (ADR-022, requires gmedia/sakala-api#208 with `SAKALA_WORKERS_ENABLED` and `SAKALA_SCHEDULES_ENABLED`). Both appear only when the workspace's `pilot-limits` says the installation turned them on (`workers.enabled`, `schedules.enabled`); otherwise nothing new is shown and the endpoints are never called. A 404 afterwards reads as "belum bisa dipakai di instalasi Sakala ini".
- Pengaturan gets a "Proses" section: `web` next to the workers, each with its command, containers (0 keeps it without running), memory and CPU ("ikut proyek" when empty), and a "Crash" badge with exit code, restarts, and since when (WIB), linking to the live deployment's log filtered to that worker. "Tambah worker" and "Ubah" open a short dialog that checks the API's rules before sending (name pattern, `web`/`release`/`job` reserved, one-line command up to 1000 characters, containers up to `max_replicas`, memory and CPU up to the workspace caps) and puts the API's own refusals on the field. The quota line says how many worker containers the workspace may run and that each also takes a running-container slot. A detected Laravel project gets "Pakai saran ini" for `php artisan queue:work --sleep=3 --tries=3 --max-time=3600`.
- Pengaturan gets a "Jadwal" section listing schedules with state ("Aktif", "Nonaktif", "Gagal N kali berturut-turut", "Dijeda otomatis"), the schedule in words, the next run in the schedule's timezone, and the last run. "Buat jadwal" opens a page with quick choices (the workspace's minimum interval when it divides an hour, hourly, daily, and weekly at a random minute so schedules do not all start at :00), the cron expression, a preview of the next three runs in WIB, and the minimum interval checked before sending. Timezone (WIB, WITA, WIT, UTC) and run timeout (default 300 s, at most 600 s) sit in a closed group. A workspace at its limit of active schedules gets a schedule that starts disabled, with the reason. A Laravel project gets the `php artisan schedule:run` suggestion at the minimum interval, with Laravel's one-minute caveat.
- A schedule's page shows its state, "Jalankan sekarang", "Ubah", "Jeda"/"Aktifkan lagi", and delete, and a paged run history in the schedule's timezone with status, start, duration, exit code, and the API's explanation for failed, timed out, lost, missed, skipped, and waiting runs. "Hentikan run" stops an open run. "Lihat log" opens a run's output inline (`?run=` links to it). A refused run now (`SCHEDULE_RUN_REFUSED`) says what to do for its `reason`. A schedule Sakala paused after failures in a row says so and offers "Aktifkan lagi".
- The deployment log names the worker of each line, gets a "Proses" filter (`Semua proses`, `web`, each worker) once workers write to it, and leaves the output of scheduled runs to the run history, with a note and a link (maintainer decision).
- The rollback dialog says that a rollback brings back the workers recorded by the target deployment, when the project has workers. The API does not expose the target's worker set, so the dialog cannot list the difference.
- A deploy refused with `PROJECT_WORKER_PROCESSES_UNSUPPORTED` says to remove the workers or wait for the server update.

### Changed

- Generated API types follow sakala-api main ea7287b, which also brings `buckets` on the project list (#205).

## [0.13.0] - 2026-11-24

### Added

- Managed S3 buckets (ADR-021, requires gmedia/sakala-api#204). `/buckets` lists the workspace's private buckets with status, usage against each bucket's own quota, attached projects, and region, under a quota card that separates what is allocated from the workspace's bucket storage from what is used. "Buat bucket" takes a name, a quota in MB (prefilled with the server default capped at what is left), and a region. The bucket page mirrors the database page: status and creation steps, a derived "Penuh" badge, attach and detach with redeploy notices, the connection (public endpoint, S3 region, bucket, access key ID, path-style) for every member, the secret key and a copyable `.env` block for owners only (audited, never cached, dropped on Sembunyikan, rotation, and navigation), key rotation with optional redeploy of attached projects and per-project outcomes, an `unknown` rotation state, quota change with a warning below current usage, rename, and delete with the name typed, blocked while attached.
- The Bucket menu appears only for a workspace opened for buckets (bucket quota above 0) or one that already holds a bucket. A workspace without quota sees "Workspace ini belum bisa membuat bucket" at `/buckets`; an installation without a storage server says so.
- The project Variabel tab lists the injected `AWS_*` variables with hidden values, marks the ones a project variable overrides ("Menimpa bucket", with a stronger warning for the key pair), and offers "Tambahkan FILESYSTEM_DISK=s3" to a Laravel project. A project without a bucket gets a quiet "Buat bucket untuk proyek ini" there and in the sleeping file note, only when its workspace can still create one; the bucket is created with `project_id`, attached in the same step.
- "Bucket" and "Penyimpanan bucket (MB)" in a limit profile's Opsional group (0 to 100 and 0 to 1,048,576; the server default is 0 for both).
- The deployment trigger `bucket_key_rotated` reads "Redeploy setelah ganti secret key bucket", and redeploy skip reasons `bucket_key_rotating`, `bucket_not_ready`, `bucket_endpoint_unavailable`, and `database_not_ready` have their own text.

## [0.12.0] - 2026-11-23

### Added

- Invite several people at once. The "Undang anggota" field takes one or more addresses separated by commas, spaces, or new lines, so a column pasted from a spreadsheet works. After a paste the dialog lists what will be left out, with the address named: a malformed one ("gita@kampus belum berupa alamat email lengkap, misalnya nama@kampus.ac.id.") and one that is already a member of the team, checked against the member list. The button counts the rest ("Kirim 3 undangan") and sends them one by one with the same role, showing "Mengirim 2 dari 3...". When everything went out the dialog closes with "3 undangan terkirim."; otherwise it stays open with what was sent and one line per address that was not, and keeps only the addresses worth fixing in the field. A rate limit (`429`) stops the rest and says how many were not sent and when to try again. Each address is still one `POST /workspaces/{id}/invitations`, so no API change is needed; the pending list is refreshed once at the end.
- "Kirim ulang" on an expired invitation. It invites the same address with the same role again, which the API turns into a new link and expiry and closes the old invitation, and confirms with "Undangan baru dikirim ke …, berlaku sampai …". "Hapus" stays as the quieter second action.
- Database limits and a default region in a limit profile, which sakala-api already accepted. In Opsional: "Database" (managed databases per workspace, 0 to 1,000; 0 means the workspace cannot create one, empty follows the server, 2 unless changed), "Penyimpanan database (MB)" (total size of the workspace's databases, 0 to 1,048,576; databases are locked while usage is at the limit and 0 locks them all, empty follows the server, 512 MB unless changed), both noting that managed databases are a limited pilot; and "Region bawaan", a select of the regions `GET app/regions` reports ("Semua region" sends `null`), which keeps a saved region no node reports anymore and says so.
- Leaving a limit profile page with unsaved changes asks first: a link inside the Console shows a confirmation, and closing or reloading the tab gets the browser's own prompt. Nothing typed, or a finished save, leaves without asking.
- A Build/jam column in the limit profiles table. An empty value reads "Bawaan" (follows the server setting) there and in Tidur otomatis (was "Ikut bawaan server"), and the Tidur otomatis column is headed "Tidur", so the ten columns and the actions fit at 1440 px.
- Rollback from the History tab (requires gmedia/sakala-api#196 and gmedia/sakala-agent v0.16.1). The row menu "Kembalikan ke versi ini" opens a dialog that compares the serving version with the target and says that variables stay as they are now, whether the old image is still on the node, and that auto-deploy pauses. A rollback deployment reads "Rollback ke #N"; when the image is gone it says Sakala rebuilt that commit.
- "Sedang melayani" badge on the deployment that serves the project, and trigger lines with names in team workspaces ("Rani, push ke main", "Rani, rollback ke #4").
- A banner while auto-deploy is paused after a rollback, with the number of held pushes and "Nyalakan lagi auto-deploy".
- Restart without a build in the Redeploy menu ("Pilihan build dan restart"), with "Sedang restart" in the header until the API reports the outcome.
- A deployment held until the project analysis finishes (`queue_state` `waiting_for_inspection`, requires gmedia/sakala-api#195) reads "Menunggu analisis proyek" and can be cancelled. The wizard no longer asks to fill in Port first for a Dockerfile app.
- A note in the first-deploy Persiapan step for apps that keep files on their own disk (Laravel, or `FILESYSTEM_DISK`/upload folder keys in `.env.example`): files written inside the container are lost when the project sleeps, restarts, or redeploys, with a link to the file storage guide. The sleeping notice says the same in one line.
- Deployment failure details link the matching section of "Saat Deploy Gagal" on sakala.dev.
- A failed health check lists the `.env.example` variables that are not filled in yet, with a link to the Variabel tab.

## [0.11.0] - 2026-11-20

### Added

- The Variabel tab says what the next redeploy will do before a variable change is saved (requires gmedia/sakala-api#186, `variable_changes`). Next to the save button of adding, editing, pasting a `.env`, and deleting a variable, one calm line reads either "Cukup restart dengan image yang sama (tanpa build)." or "Perubahan ini butuh build ulang karena …" with the reason:

## [0.10.0] - 2026-11-19

### Added

- Variables from `.env.example` and a database before the first deploy (requires gmedia/sakala-api#184 and the agent's protocol revision 4). Once inspection has read the repository, the wizard's last step shows a Persiapan phase when there is something to confirm, led by what Sakala already did ("Sakala sudah membaca … dan menyiapkan 18 variabel. Tinggal pilihan database dan 2 variabel yang perlu kamu isi."). A database card says why in plain words ("Sakala menemukan DB_CONNECTION di .env.example dan migration Laravel di database/migrations.") and offers a new database for the project (preselected when likely and possible), an existing one of the workspace (unusable ones listed with the reason), or none; it is honest that MySQL apps get PostgreSQL and that SQLite data is lost on every deploy, says why a new one cannot be made (no database server, quota full), and prefills the suggested release command when the project has none. Variables are grouped: "Perlu kamu isi" (credential-like names, empty inputs, a safe example as hint, skipped when empty) is open; "Dibuatkan Sakala" (APP_KEY, SECRET_KEY_BASE, auth and session secrets, generated with Web Crypto and stored as secrets), "Dari .env.example" (with production values for APP_ENV, NODE_ENV, APP_DEBUG, and the project address for APP_URL, NEXTAUTH_URL, AUTH_URL), and "Diisi Sakala" (PORT, and the DB variables with a database) are closed groups with counts and names; keys the project has are listed once and left alone. "Deploy sekarang" saves the release command and the variables one by one (with the existing fix-or-continue step on refusals), then creates the database with `project_id` and `deploy_when_ready`, waits for it with the provisioning steps, and opens the deployment the API starts. The Variabel tab gains "Isi dari .env.example", and the overview's next step links to it. `getInspectionNotes` no longer tells users to compare `.env.example` by hand when the suggestions exist. API types regenerated from sakala-api 3ce1f6b.
- Skipped monorepo pushes in Riwayat (requires gmedia/sakala-api#181). A push that only changed files in other projects' folders no longer deploys the project, and the history shows it as a quiet row right above the deployment it followed: "Dilewati — tidak ada perubahan di apps/web", with the commit message, short SHA, branch, and time, a dashed outline instead of a status dot, no number, no link, and no error colour. An info button opens a short explanation of the rule (changes inside the project's folder deploy it, changes in another project's folder deploy only that one, shared files outside every project folder deploy all, and anything uncertain such as a force push deploys all) and up to 5 of the changed files with a count of the rest. One request per history page (`since` the oldest deployment shown); a search shows deployments only; an API without the endpoint leaves the history unchanged.
- Password rotation that says when it is done (requires gmedia/sakala-api#182). The "Ganti password" dialog explains that the old password stops working as soon as the database server changes it and that attached apps cannot open new connections until they are redeployed, with "Redeploy otomatis proyek yang terpasang" checked by default (sent as `redeploy_attached`). The section then shows the rotation from `password_rotation`: a pending line while the node works (polled every 2 s, only while pending or while the redeploys are being queued), "Password sudah diganti pukul HH.MM", and one row per attached project: the queued redeploy with a link to its deployment, "Sudah memakai password baru" once it serves, a first-deploy note for a project never deployed, or "Masih memakai password lama" with a Redeploy button and the reason the API skipped it. A failed rotation keeps its explanation. The old local "Penggantian password diminta" note and the rotation redeploy notice are gone. Deployments with trigger `database_password_rotated` read "Redeploy setelah ganti password database".
- "Database terkelola belum tersedia di server ini" on the Databases page when `GET app/pilot-limits` reports `databases.available: false` (gmedia/sakala-api#182): a calm empty state with one line why, no "Buat database", and existing databases still listed under the same notice. The sidebar item stays, so the page can still be found and explains itself. An API without the flag counts as available.

- JavaScript monorepos (requires sakala-api with `stack.monorepo`, gmedia/sakala-api#179, and sakala-agent #113). When a project's root directory is a package of an npm, pnpm, Yarn, or Bun workspace, the wizard's detection result says "Monorepo pnpm terdeteksi — build dari root workspace, aplikasi dari apps/web" with the workspace root, the package, and the build and start commands derived from its `package.json` (a missing script is said in words; a Vite build with no start command reads as served as a static site), plus a note that commands set in Pengaturan take their place. The deployment timeline shows the same line under "Menganalisis proyek", with the commands the deployment really ran, from its `deployment.workspace.detected` event (under "Build proyek" for an agent that sends no analysis event). An API without the field, and metadata of another shape, show nothing extra.
- Paste a whole `.env` file. "Tempel dari .env" sits under the variables in the create wizard and next to "Tambah variabel" on a project's Variabel tab, and pasting several lines into the variable name field opens it too. The text is read with dotenv's own `parse` (quotes, comments, `export`, multi-line values), and a preview says "10 variabel terbaca: 8 baru, 2 sudah ada" and lists every key with its fate. Keys that already exist are skipped unless "Timpa dengan nilai yang ditempel" is picked; nothing is overwritten silently. Everything is stored as a secret by default; when that is turned off, values that look like credentials (names such as `PASSWORD`, `TOKEN`, `_KEY`, or values such as URLs with a password, GitHub, Stripe, Slack and AWS tokens, JWTs, Laravel keys, private keys) stay secret and are named. `PORT` is never added, because Sakala gives the app its PORT from the project's port and a different one fails the deployment; in the wizard its value becomes the project port when none is set. Empty values, invalid names, and unreadable lines are listed as skipped. On the Variabel tab new keys are saved with `POST` and overwritten keys with `PATCH`, one at a time, and the ones that fail are named.
- "Belum punya repo? Coba dengan contoh" on the wizard's repository step: Situs HTML statis, Node.js dan Express, and Laravel, from one examples repository listed in `src/lib/config/starter-examples.ts` (`STARTER_EXAMPLES`). Picking one fills the public URL, root directory, release command, and a project name, clears port, build, and start (each example leaves them to detection; Laravel builds from its own Dockerfile), adds the variables it needs, checks the repository with the API, and opens the configuration step with a note on what was filled in, which variables are optional, and how to fork it. Laravel runs `php artisan migrate --force` as its release command, gets a fresh `APP_KEY` (32 random bytes from Web Crypto, stored as a secret), and names `DATABASE_URL` as optional, since the app explains how to connect a database without it. The empty project list links each example (`/projects/new?example=<id>`), and the onboarding welcome has "Coba dulu dengan repo contoh", which opens the wizard at `#contoh`.
- "Bagikan" and "Kode QR" on the first-live screen. Bagikan opens the system share sheet (Web Share API) where the browser has one, and copies the address when the share fails; elsewhere Salin stays the way to share. Kode QR opens a dialog with a QR code of the address, drawn as one SVG path from `uqr` (zero dependencies, a port of Nayuki's reference encoder), which loads only when the dialog opens.
- "Salin ringkasan error" on a failed deployment, next to "Lihat error di log". It copies plain Indonesian text that reads on its own in a chat: project, deployment number, branch and commit, the stage, failure code, summary, the fix hint, the detail, and up to the last 30 stderr lines of the failing stage (no stdout), each line with its time. Everything passes through a redaction step that masks URLs with a password, `NAME=value` with a secret-sounding name, bearer tokens, private keys, and GitHub, Stripe, Slack, AWS, Google, JWT, and Laravel keys, and the text ends with "Periksa dulu sebelum dibagikan", which the toast repeats.
- Log tools in the deployment log: a search field (`/` focuses it, case-insensitive) with "x dari y baris", "Hanya error" with the number of error lines, line numbers in the gutter that link to `#L<n>` (clicking puts the permalink in the address; opening one loads older pages until that line is there, then scrolls to it and highlights it), and "Unduh .txt", which saves the loaded log as `<proyek>-deployment-<nomor>.txt`. The toolbar stays one row on a 1280 px screen (copy and download are icon buttons with names below 1536 px) and wraps on narrow screens.
- Email column in notification settings (requires sakala-api with `email` in `notification-preferences`, gmedia/sakala-api#177): every category has a "Lonceng" switch, and Deployment berhasil, Deployment gagal, and Masalah proyek also have an "Email" switch; Tim and Keamanan akun say "Email penting selalu dikirim". An API without `email` reads as its defaults (success off, failure and problems on).
- `/notifications/unsubscribe`, the public page behind the unsubscribe link in Sakala emails. It names the category in Indonesian and changes nothing until "Ya, matikan email ini" is pressed, because mail scanners open every link. It then posts the query string exactly as received to `api/v1/public/notifications/unsubscribe`, without cookies or CSRF (`apiRequest` gains `anonymous`), and explains each answer: done (with a link to the settings when signed in), invalid link (403, also for a link missing its signature, without asking the API), deleted account (404), a category without email (422), and too many requests (429, with the wait when the API sends it).
- Managed databases, phase 1 (requires sakala-api with managed PostgreSQL databases, gmedia/sakala-api#178). Databases belong to the workspace, live next to Proyek in the sidebar as "Database", survive project deletion, and attach to any number of projects in the same workspace (one database per project).
  - `/databases` lists the active workspace's databases with name, status in words (Menyiapkan, Siap, Gagal, Menghapus, Terkunci) and a one-line reason where one is needed, size against the workspace storage quota, attached projects, and region, under a quota summary such as "1 dari 2 database" and "12 MB dari 512 MB" (warning at 80 %, full at 100 %). An empty workspace explains what a database is and offers "Buat database"; viewers get no create action.
  - "Buat database" asks for a name and a region ("Otomatis" by default, naming the workspace's default region such as "Otomatis (jkt)", or the project's region when opened from a project) and explains quota, storage, and region refusals with their numbers. A used-up quota is explained before the form.
  - The database page (`/databases/{id}?workspace=…`) shows the status with the provisioning steps (polled every 5 seconds only while the node works), the lock explanation with the workspace's usage, attached projects with attach and detach (each followed by a note to redeploy that project, linking to its Variabel tab), connection details, password rotation with a confirmation that names the projects to redeploy, the extension allow-list, a release command hint for migrations, rename, and delete, which is blocked while projects are attached.
  - Host, port, database, and user are shown to every member (from `connection`, sakala-api#180). The password and `DATABASE_URL` are shown only to workspace owners and admins, only after "Tampilkan password", never cached, and with a note that every reveal is audited. Members and viewers see why they are hidden.
  - The attach dialog lists the workspace's projects and disables the ones that already use another database ("memakai <nama>"), from the project list's `databases`.
  - On the project side, the Ringkasan diagram draws the attached database in "Terpasang" with its status and a link to its page, and the Variabel tab lists the injected `DATABASE_URL` and `DB_*` variables read-only, flags the ones a project variable overrides, and gives Laravel projects without a release command the migration hint.

- Login, register, forgot-password, resend verification, and account settings follow `GET /api/v1/auth/options`: email-based options and unconfigured providers are not offered, with a plain explanation, and `EMAIL_DELIVERY_UNAVAILABLE` shows the API's message.
- Initial SvelteKit static SPA foundation.
- Sakala design tokens and sidebar-based application shell.
- Sanctum-aware API client, typed errors, and TanStack Query foundation.
- OpenAPI type generation, unit/component/E2E testing, CI, and contributor documentation.
- Accessibility floor spec (`tests/e2e/a11y-floor.spec.ts`) over every route at 320, 768, 1024, 1280, and 1366 px, and a colour token contrast spec (`src/lib/design-tokens.spec.ts`).
- Skip link, a focus-trapped mobile drawer, and a lint rule against hex colours in `.svelte` class strings.
- A notice on the login page when a session ends by itself, and a clear message for `GITHUB_RATE_LIMITED` with its wait time.

### Changed

- The deployment page has two columns from 1024 px: stages and facts in 260 px, and the terminal filling the rest down to the bottom of the viewport. On smaller screens the log comes first and the rest folds away.
- The terminal has columns for time and stream, labels and tints stderr, shows a cursor while the process runs, and carries its own follow and copy controls. "Lihat error di log" jumps to the first stderr line.
- The first deployment of a project to succeed says `<project> sudah live` with the address, open, and copy together. Later ones stay calm, and a deployment whose app keeps crashing no longer reads as a plain success.
- Stages show how long each one took, and the page shows the commit message and links the SHA to GitHub.
- Deployment history is one row per deployment, with the whole row as the link and two levels on phones. A project that never deployed no longer offers filters.
- The project header leads with the address as a link. Project settings are one column with the same fields as the wizard, and the delete dialog states the real retention.
- The wizard folds port, build, start, and root directory under "Pengaturan lanjutan", and opens it by itself on an error. Esc clears the draft in its env editor. On phones the stepper reads "Langkah 2 dari 3".
- Re-reading deployment events continues from the last page instead of walking all of them again.
- Colour tokens meet WCAG 2.2 AA: 4.5:1 for text and 3:1 for control edges and the focus ring. Figma's `#A2A2A2` secondary text became `#6B6B6B`.
- Project links use `public_url` from the API instead of building `https://` from the domain.
- Interface wording is consistent: `Proyek`, `Pengaturan`, and `kamu`. Unsubstantiated claims on the auth and onboarding screens were replaced with what the product does.
- Times use `08:41:02`, with the date when older than today, and durations read as `2 menit 5 detik`. A failed step shows when it failed.
- Fonts are self-hosted with `font-display: swap`; the Google Fonts import is gone. Sources and licences are in `static/fonts/README.md`.
- Inter is self-hosted for reading text, with Montserrat for headings and one JetBrains Mono file for code. Text uses one scale of 12, 14, 16, 20, 24, 32, and 48 px and three weights, and `design-tokens.spec.ts` rejects anything else.
- `Button` has fixed sizes and variants, every field shares `.control-input` and one focus style, and controls, cards, and overlays have one radius each. Only overlays have a shadow.
- The sidebar becomes a drawer up to 1024 px, with a small S mark in the mobile header. Notification rows put the time under the text on narrow screens.
- A running deployment is teal, and a queued one uses a new `#C2670E` token. Status names come from one dictionary.
- Login and register share one layout with the logo on mobile, and the hero shows a labelled sample flow without the glow. Tab titles follow `page · project · Sakala`, and every logo link stays in the Console.
- Onboarding asks for the profile first, the source question stays optional, and it ends on the new project page.
- Project cards are whole links without a thumbnail box, and the list shows filters only for more than six projects, defaulting to all time.
- Deleting a project confirms with a toast (`svelte-sonner`), and its dialog says the data goes after the retention period and the address is not reused.

### Removed

- `static/icons/load.svg`, whose origin is not recorded, the 1.26 MB `bg.png`, and unused logo files.
- Dead code: `ApiStatusCard`, `ConfirmDialog`, `Select`, the system status resource, and `api/envelope.ts`.
